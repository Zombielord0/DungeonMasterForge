# Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Whispers become two-way DM ↔ player chats, and the players get a party chat that the DM can't see.

**Architecture:** Keep the `whispers` table. Player replies are rows to the DM, and party messages are rows with `to_user_id = 'party'`. A new `chat_reads` table holds each player's read position in the party chat. The API decides who sees what. `src/portal.js` gets one chat model (load, poll, unread counts per thread) and one bubble renderer, used by the player's Chat tab and by the DM's Chat card on the Party tab.

**Tech Stack:** Vanilla JS (`src/portal.js`, bundled by esbuild), Netlify Functions (`netlify/lib/api.mjs`), Postgres migrations, node:test with PGlite, and Playwright.

**Spec:** `docs/superpowers/specs/2026-11-24-chat-design.md`

## Global Constraints

- **The DM never receives a party row**, from any route.
- **A player only receives** rows they sent or received, plus party rows.
- Message length is at most 2,000 characters (`MAX_WHISPER`); empty messages are refused with 400.
- A player may send only to `"dm"` or `"party"`. The DM may send only to a player id in the campaign.
- All message text and names are rendered through `esc()`. No `onclick=` attributes: use delegated `data-` attributes (the page guard strips handlers).
- **Polling:** every 3 seconds while a chat conversation is on screen and the page is visible; every 8 seconds otherwise; nothing while `document.hidden`.
- Keep the view id `#whispers` and the element ids `#whispersMain`, `#whisperN` and `#whisperAlert`, so old links and `14-boot.js` keep working. The tab's label becomes "Chat".
- Copy that the spec fixes: the tab is labelled **Chat**; the conversations are named **DM** and **Party**; the banner gets a **Reply** button.
- New e2e check: `npm run test:chat` on port **8893**.

## Review Focus

1. **A poll redraw while someone is typing.** The draft text, the caret and the focus must survive. Only the message list is redrawn, never the composer. (Test in Task 2.)
2. **Scrolling while reading older messages.** A new message must not jump the view to the bottom unless the reader was already within 40 px of the bottom. Opening a conversation starts at the bottom. (Test in Task 2.)
3. **A removed player still has the tab open.** Polling gets a 403: stop the chat timer quietly, without error toasts or a page error. (API test in Task 1, browser test in Task 3.)
4. **Enter pressed twice fast, or Enter while composing accented text.** Exactly one message is sent. Ignore Enter while `e.isComposing`, and disable Send until the request finishes. (Test in Task 2.)
5. **A long word or URL with no spaces.** The bubble wraps (`overflow-wrap:anywhere`) and never widens the page on a 390 px phone. (Test in Task 2.)

### Task 1: API and database

**Files:**
- Create: `netlify/database/migrations/20261124120000_chat.sql`
- Modify: `netlify/lib/api.mjs` (the `// ---- whispers ----` block, about lines 484–512)
- Test: `test/api.test.mjs`

**Interfaces:**
- Produces, `GET campaigns/:cid/whispers`: an array, newest first, of
  `{ id, thread, from, fromName, to, toName, body, at, mine, read }`.
  - `thread` is `"dm"` or `"party"` for a player, and the player's user id for the DM.
  - `mine` is true when the caller sent the message.
  - `read`:
    - for a one-to-one message, it's `read_at` set;
    - for a party row, it's `id <= the caller's chat_reads.last_read_id`;
    - a message you sent always counts as read.
  - Limits:
    - the DM gets the latest 400 non-party rows;
    - a player gets the latest 200 of their own rows plus the latest 200 party rows, merged newest first.
  - `fromName` comes from `members.display_name`, or `"A former player"` when the sender has left.
- Produces, `POST campaigns/:cid/whispers` `{to, body}` returns 201 `{id, at}`.
  - DM: `to` = a player id, as now.
  - Player: `to` = `"dm"` (the server looks up the member with `role = 'dm'`) or `"party"`. Anything else returns 400 "Send to your DM or the party".
- Produces, `POST campaigns/:cid/whispers/read` `{thread}`:
  - DM with a player id: sets `read_at` on that player's rows to the DM;
  - player with `"dm"`, or with no body (old clients): sets `read_at` on rows to the player;
  - player with `"party"`: upserts `chat_reads.last_read_id` to the newest party id;
  - DM with `"party"`: 403.

**Interfaces:**
- Consumes: the Task 1 API.
- Produces, in `portal.js`. Task 3 uses all of these:
  - `S.chat = { msgs: [], open: null }`. `open` is the thread on screen (`"dm"`, `"party"` or a player id), or null.
  - `loadChat(): Promise<void>`: GETs, stores `S.chat.msgs`, calls `showUnread()` and redraws whichever chat view is on screen. On a 403 it calls `stopChat()`.
  - `chatUnread(thread: string): number`: counts messages with `!mine && !read` in that thread.
  - `chatListHTML(msgs, {names: boolean}): string`: bubbles oldest first. Use `li.mine` / `li.theirs`; show the sender's name when `names` is set; show the time as `clock(at)`, with the full date in `title`.
  - `chatComposerHTML(thread: string): string`: a `<form class="chat-form" data-chat-to="…">` with a `<textarea maxlength="2000" aria-label="Message">` and a Send button.
  - `drawChatList(host: Element, thread: string, names: boolean)`: replaces only `host.querySelector(".chat-list")`. It keeps the scroll at the bottom if the reader was within 40 px of it, and scrolls to the bottom when the thread changes.
  - `chatRead(thread)`: optimistic `read = true` locally, then POST `whispers/read {thread}`.
  - `startChat()` / `stopChat()`: a `setTimeout` loop, 3000 ms when `S.chat.open` is set and visible, otherwise 8000 ms. It replaces `S.whisperTimer`. `stopLoops()` calls `stopChat()`.
  - Delegated handlers:
    - `submit` on `.chat-form` POSTs `{to: data-chat-to, body}`, with Send disabled while it's in flight. It clears the textarea only on success, then runs `loadChat()`.
    - `keydown` Enter (without Shift, and not while `isComposing`) inside `.chat-form textarea` calls `requestSubmit()`.
